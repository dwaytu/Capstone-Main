# Phase 4 Plan 01: Cross-Platform Smoke And Release Verification

## Objective

Verify that the current SENTINEL source can deliver the web, desktop, and Android targets, and that the operational map and tracking APIs work for command and guard roles.

## Scope

- Validate production web environment gates against the Railway backend.
- Build the Android web bundle and synchronize Capacitor assets/plugins.
- Build the desktop Tauri application and Windows installers.
- Exercise command and guard map surfaces at desktop and mobile viewports.
- Verify tracking map, active-guard presence, and client-site endpoint contracts with role-aware authorization expectations.
- Record runtime, console, request, API, and layout failures.

## Verification Commands

```text
npm run release:web
npm run build:android
npm run build:desktop
npm run audit:phase4
```

The browser audit is repeatable with `AUDIT_*` credentials and writes screenshots to `DasiaAIO-Frontend/test-results/phase4/`.

## Acceptance Criteria

1. Production web environment validation passes without local/private API targets.
2. Android build and Capacitor synchronization complete.
3. Desktop application and Windows MSI/NSIS installers build successfully.
4. Command and guard maps render on desktop and mobile with visible map tiles.
5. `/api/tracking/map-data` and `/api/tracking/active-guards` return valid `200` payloads for both tested roles.
6. Guard access to admin-only `/api/tracking/client-sites` remains denied with a valid authorization error.
7. No browser page errors, unexpected console errors, failed requests, API errors, or horizontal overflow are present.

## Implementation Note

The audit found and fixed a direct-link routing defect: `/operations-map` was missing from `AppShell`'s elevated operational-shell route set, causing the dashboard to render instead of the map on direct navigation.
